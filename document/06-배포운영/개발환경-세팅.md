# 개발 환경 세팅 (새 머신에서 이어서 작업하기)

> 이 문서는 완전히 새 머신(예: 집 PC)에 **VirtualBox + Ubuntu 게스트 VM**만 설치된 상태에서
> 시작해, 이 저장소를 clone하고 지금과 동일한 개발 환경을 그대로 재현하는 절차입니다.
> Claude Code에게 "이 문서대로 세팅해줘"라고 하면 아래 순서를 그대로 실행하면 됩니다.

## 0. 전체 구조

```
1.shopping-mall/
├── backend/    Spring Boot API (Java 21, Gradle) — DB/인증/상품 API
├── frontend/   Next.js 웹 — 아직 스캐폴딩만, 미착수
├── mobile/     Expo(React Native) 앱 — 진행 중, 백엔드와 실제 연동됨
├── document/   기획/요구사항/설계/개발로그
└── infra/      VM 안에서 Docker Compose로 띄우는 PostgreSQL + Jenkins 정의
```

백엔드는 **VM 안의 Postgres**에 `127.0.0.1:5432`로 접속합니다(VirtualBox NAT 포트포워딩).
DB 스키마/시드 데이터는 백엔드가 기동할 때 Flyway가 자동으로 적용하므로 手동으로 SQL을
실행할 필요가 없습니다.

## 1. 준비물

- 호스트: VirtualBox (설치됨), Node.js 20+, JDK(아무 버전이나 — 21 이상 권장, Gradle
  toolchain이 컴파일용 21은 알아서 내려받음), Git
- VirtualBox 게스트: Ubuntu (24.04/26.04 등 최신 LTS) — 아래 절차로 새로 설치

## 2. VM 생성 및 SSH 설정

1. VirtualBox에서 새 VM 생성: 이름은 자유(예 `test-server-vm`), OS Type `Ubuntu (64-bit)`,
   메모리 8192MB, CPU 2코어, 네트워크는 **NAT**(기본값).
2. Ubuntu 설치. 사용자명은 `test`로 맞추면 아래 예시 명령을 그대로 쓸 수 있습니다(달라도
   명령어의 `test@`만 바꾸면 됨).
3. VM 안에서 SSH 서버 설치:
   ```bash
   sudo apt update && sudo apt install -y openssh-server
   sudo systemctl enable --now ssh
   ```
4. 호스트에서 새 키 페어 생성(기존 VM용 키는 재사용하지 않음 — 새 VM이므로):
   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/shopping_mall_vm -C "shopping-mall-vm" -N ""
   ```
5. 생성된 `~/.ssh/shopping_mall_vm.pub` 내용을 VM 안 `~/.ssh/authorized_keys`에 추가
   (VirtualBox 콘솔에서 직접 입력하거나, 임시로 비밀번호 로그인 켜서 `ssh-copy-id` 사용).
6. VM을 끈 상태에서 포트포워딩 규칙 3개 추가:
   ```bash
   VBoxManage modifyvm test-server-vm --natpf1 "SSH,tcp,,2222,,22"
   VBoxManage modifyvm test-server-vm --natpf1 "postgres,tcp,127.0.0.1,5432,,5432"
   VBoxManage modifyvm test-server-vm --natpf1 "jenkins,tcp,127.0.0.1,8080,,8080"
   ```
7. VM을 헤드리스로 켜고 접속 확인:
   ```bash
   VBoxManage startvm test-server-vm --type headless
   ssh -i ~/.ssh/shopping_mall_vm -p 2222 test@127.0.0.1
   ```

## 3. 이 저장소 clone + VM 안에 인프라 기동

1. 호스트에서 저장소 clone (경로는 자유):
   ```bash
   git clone <이 저장소 remote 주소> 1.shopping-mall
   ```
2. `infra/` 폴더를 VM 안으로 복사 (scp 또는 VM 안에서 저장소를 다시 clone해도 됨):
   ```bash
   scp -i ~/.ssh/shopping_mall_vm -P 2222 -r infra test@127.0.0.1:~/shopping-mall-infra
   ```
3. VM 안에 Docker 설치:
   ```bash
   curl -fsSL https://get.docker.com | sh
   sudo usermod -aG docker $USER
   # 재로그인(exit 후 재접속) 필요
   ```
4. 환경변수 파일 준비 (`infra/.env.example` → `infra/.env`, 값 채우기):
   ```bash
   cd ~/shopping-mall-infra
   cp .env.example .env
   # POSTGRES_PASSWORD: 원하는 값으로 (백엔드 application.properties 기본값과 맞추려면
   #   qiV4KHzp5lfgbrHj62XL 그대로 써도 됨 — 개발용이라 상관없음)
   # DOCKER_GID: `getent group docker`로 나온 GID 값으로 채우기
   sed -i "s/DOCKER_GID=.*/DOCKER_GID=$(getent group docker | cut -d: -f3)/" .env
   ```
5. 기동:
   ```bash
   docker compose up -d
   docker compose ps   # postgres, jenkins 둘 다 Up/healthy 확인
   ```

## 4. 스키마 적용

따로 할 일 없음 — 5번에서 백엔드를 처음 띄우는 순간 Flyway가 `backend/src/main/resources/db/migration/`의
`V1__init_schema.sql`(전체 스키마 55개 테이블) → `V2__seed_dev_data.sql`(관리자 테스트 계정 +
더미 상품 10개)를 자동으로 순서대로 적용합니다.

## 5. 백엔드 실행 (호스트)

1. JDK 확인: `java -version` (없으면 아무거나 설치, 예: `sdk install java 21-tem` 또는
   IntelliJ 내장 JDK 사용)
2. 실행:
   ```bash
   cd backend
   ./gradlew bootRun          # macOS/Linux
   # 또는 Windows: run-dev.bat, 또는 IntelliJ에서 BackendApplication 실행(▶)
   ```
3. 확인: `http://localhost:8090/docs` (Swagger UI) 열리면 성공.
4. 테스트 로그인 (`POST /api/auth/login`): `admin@mall.test` / `Mall!2026`

포트 8090을 쓰는 이유: 8080은 Jenkins가 이미 쓰고 있어서 피함
(`backend/src/main/resources/application.properties`의 `server.port` 참고).

## 6. 모바일 앱 실행

```bash
cd mobile
npm install
npx expo start --web    # 웹 미리보기 (제일 빠름, http://localhost:8081)
# 실제 폰(Expo Go)으로 보려면: npx expo start (QR 스캔)
#   → 이 경우 src/constants/api.ts의 API_BASE_URL을 localhost 대신
#     이 머신의 LAN IP(예: http://192.168.0.12:8090)로 바꿔야 폰에서 접근 가능
```

홈 화면에서 상품 10개(백엔드 DB에서 실시간으로 불러옴)와 정렬 버튼이 보이면 성공.

## 7. 지금까지 완성된 것 / 안 된 것

**완성**
- DB 스키마 1차 완성판 (55개 테이블, `document/03-설계/schema.sql` · `ERD.md`)
- 백엔드: 회원가입/로그인(JWT), 상품 목록/상세 조회 API, 전역 예외처리, 파일 정적 서빙,
  CORS
- 모바일: 디자인 토큰(테크팩 스펙시트 컨셉) + 재사용 컴포넌트(Button/TextField/Tag/
  ProductCard/OrderSummary/Table/SortBar) + 스타일가이드 화면 + 백엔드 연동 홈 화면

**미착수**
- 상품 상세 화면, 장바구니/주문/결제 플로우
- 로그인/회원가입 화면(API는 있지만 앱 UI 없음)
- 리뷰/위시리스트/마이페이지, 관리자단
- 프론트(Next.js 웹)는 스캐폴딩만 돼 있고 손 안 댐(앱 먼저 진행하기로 결정)

## 8. 알아둘 것

- `application.properties`에 DB 비밀번호/JWT 시크릿이 개발용 기본값으로 하드코딩돼 있음
  (`${DB_PASSWORD:qiV4KHzp5lfgbrHj62XL}` 등). 실제 배포 전에는 반드시 환경변수로 분리
  필요 — 사용자가 "아직"이라고 해서 보류 중인 항목.
- 백엔드 정적 파일(상품 이미지)은 `backend/storage/uploads/`에 실제로 커밋돼 있음(시드
  데이터가 참조하는 고정 자산이라 예외적으로 git에 포함).
- `backend/gradle.properties`는 의도적으로 커밋하지 않음 — 특정 머신의 JDK 절대경로를
  박아두면 다른 머신에서 깨지기 때문. JDK가 PATH/JAVA_HOME에 잡혀 있으면 별도 설정 불필요.
